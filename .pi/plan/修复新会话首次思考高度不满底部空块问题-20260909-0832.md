## 修复新会话首次思考高度不满底部空块问题

### 现状

新会话第一条用户消息发送后，Conversation 区只有一个用户泡泡 + 一个
ExecutionFlow / Thinking 过程块。当这些内容的高度小于 `.conversation` 滚动
视图的 clientHeight 时，`.messages` 容器下方出现大片的空白区域（在消息底部
和扩展坞底座之间），视觉上不连贯。

### 方案

修改 `src/renderer/styles.css` 中 `.messages` 的样式，
使其始终撑满滚动视图的高度，并在内容不足时通过 flex 撑杆将内容推到靠下位置
（贴近扩展坞）。这样留白就出现在内容上方（被顶部渐隐 mask 自然过渡掉），
而不是下方。

### 具体变更

**文件：`src/renderer/styles.css`**

找到 `.messages` 选择器，替换为：

```css
.messages {
  width: var(--col);
  padding: 28px 28px 20px;
  margin: 0 auto;
  display: flex;
  flex-direction: column;
  min-height: 100%;
}
```

并在 `.messages > :last-child` 之前（或 `.messages` 内部末尾）插入一个 flex 撑杆：

```css
.messages::after {
  content: "";
  flex: 1;
  pointer-events: none;
}
```

- `display: flex; flex-direction: column;` — 让 `.messages` 变为弹性列容器
- `min-height: 100%` — 始终撑满 `.conversation` 的滚动视口高度
- `::after` flex 撑杆 — 在内容不足时把真正的消息块推到下方，使最后一条
  内容贴近扩展坞；随着消息累积超越视口高度，flex 撑杆自然缩为 0，不影响
  正常滚动

### 验证

1. 新会话，发送第一条消息 → 观察 thinking 过程是否贴近扩展坞上方，底部不再有空块
2. 多次提问，消息堆满一屏以上 → 正常滚动，flex 撑杆失效，行为不变
3. 切换深色/浅色主题 → 无视觉异常
4. 回到底部按钮 / progress overlay 定位不受影响（它们使用 `--dock-clearance`，不依赖 `.messages` 高度）
