# TACode 使用稳定性加固方案

## 当前基线与范围

- 已检查 Electron 主进程、Agent RPC 宿主、React 状态流、会话持久化、IPC、内置浏览器和现有测试。
- 当前基线：`pnpm typecheck` 通过；`pnpm test` 通过，39 个测试文件、363 项测试全部通过。
- 工作区已有未提交的 renderer 改动：`src/renderer/conversation.test.ts`、`src/renderer/conversation.ts`、`src/renderer/styles.css`、`src/renderer/ui.tsx`；实施时保留，不覆盖或回退。
- 本方案不改变 Agent 核心协议和权限语义，不引入遥测；日志和恢复信息只保存在本机。

## 主要稳定性风险（按优先级）

### P0：会话切换和数据一致性

1. `src/main/index.ts` 通过全局 `activeSessionPath` 路由 `agent:command`，快速切换项目/会话或并发 `agent:start` 时，旧请求可能在新会话上执行；`agentHosts` 在会话文件变更后还可能留下同一个 host 的路径别名。
2. `AgentHost.snapshot()` 期间 renderer 会丢弃事件，切回后台流式会话时可能出现快照与后续事件之间的缺口。
3. `BrowserAutomation` 是全局实例，`workingTabId`、串行队列和 `resetAgent()` 未按 Agent host 隔离；多个后台 Agent 可能互相清理引用、抢占目标标签或取消对方操作。
4. `loaded-sessions.json`、设置、最近项目、Vision/Chat/MCP 等 JSON 文件仍有直接 `writeFile`；崩溃或掉电可能留下截断 JSON。首条 prompt 的受保护消息也是 fire-and-forget 写入，最脆弱窗口仍可能丢消息。

### P1：资源、边界和恢复体验

1. 多个 IPC handler 只依赖 TypeScript 类型，图片、恢复文件、prompt、浏览器数据和 RPC 单行没有统一大小上限，异常输入可能造成主进程内存压力。
2. 主窗口 renderer 崩溃/重载、worker 异常退出、浏览器 guest 崩溃时缺少统一的状态恢复和可操作提示；部分关键错误被静默 `catch`。
3. 浏览器下载记录永久保留，guest/监听器和浏览器操作队列缺少完整的生命周期清理；工作区 watcher 出错后也没有可靠重试。

## 实施步骤

### 阶段 1：建立 session-bound Agent 生命周期（P0）

**涉及文件**

- 新增 `src/main/agent-manager.ts`，集中管理 host、运行代次、启动/停止锁和会话重绑定。
- 修改 `src/main/agent-host.ts`、`src/main/index.ts`、`src/shared/types.ts`、`src/preload/index.ts`、`src/renderer/App.tsx`。

**行为**

- 为每个 Agent host 分配稳定的 `runtimeId`，不再只用可变化的 session 文件路径作为唯一键。
- `agent:start`、`agent:stop`、`agent:command`、`agent:ui-response` 带上目标 runtime/session handle；主进程按 handle 路由，不依赖易变的全局活动会话。
- 对同一 runtime 的 start/stop/command 做串行化；切换会话只改变 renderer 的活动 handle，不会让旧请求改写新会话的活动状态。
- session 文件产生或变更时通过统一 `rekey` 更新索引，消除旧路径别名；退出时每个 host 只 stop 一次。
- Agent 事件和错误带 `runtimeId` 与递增序号；为 snapshot 建立短期事件回放缓冲，打开/切回会话时先应用一致快照，再补齐 snapshot 期间到达的事件。
- 增加运行中 host 的查询/恢复接口，使 renderer 重载后可以重新发现运行中的会话，而不是只依赖已经错过的事件。
- `App.tsx` 用启动 epoch/取消令牌统一处理 `newThread`、切项目、切会话、关闭设置等操作；第二次 sandbox 确认不会让第一次等待永久挂起；过期 start 不得复活旧界面。

**验收**

- 快速在 A/B 两个会话间切换、连续点击打开同一会话时，不出现命令发到错误会话、旧 host 重复 spawn 或旧事件污染当前 transcript。
- renderer 重载后能重新打开运行中会话并看到一致的消息、运行态和错误态。

### 阶段 2：按 runtime 隔离内置浏览器（P0/P1）

**涉及文件**

- 修改 `src/main/browser/automation.ts`、`src/main/agent-host.ts`、`src/main/index.ts`、`src/main/browser/ipc.ts`、`src/renderer/browser/browser-panel.tsx`、`src/main/browser/windows.ts`、`src/main/browser/downloads.ts`。

**行为**

- `BrowserAutomation` 的 working tab、队列、取消和 ref 失效范围改为 runtime 级；一个 Agent 的 `resetAgent` 不得清理其他 Agent 的页面引用。
- 浏览器 tab 登记携带 runtime/owner 归属，目标标签校验归属；过期或已取消的排队操作不再继续执行，并设置队列上限。
- 为 guest/owner 销毁、renderer gone、窗口关闭统一注册清理函数，移除事件监听、presentation waiter、tab 映射和 debugger 引用。
- detached browser 的自动 reload 增加退避与最大重试次数；持续崩溃时显示可重试的错误页而不是无限 reload。主面板 webview 同样显示加载失败/guest 崩溃状态。
- 下载历史设置数量上限和过期清理，保留进行中任务；工作区 watcher 失败后进行有限重试或明确提示需要刷新。

**验收**

- 两个后台 Agent 同时使用浏览器时不会互相切页、失效 ref 或取消动作。
- guest 崩溃、独立窗口关闭、切换项目和应用退出后无残留 worker、tab 映射或无限重载。

### 阶段 3：统一持久化与首条消息保护（P0）

**涉及文件**

- 新增 `src/main/atomic-file.ts`（同目录临时文件、必要时 `fsync`、rename、权限设置、串行写队列）。
- 修改 `src/main/index.ts`、`src/main/provider-store.ts`、`src/main/providers.ts`，并为 `src/main/atomic-file.test.ts` 增加测试。

**行为**

- 将 `loaded-sessions.json`、`settings.json`、`recent-workspaces.json`、`chat-profiles.json`、`vision-config.json`、`web-search.json`、`mcp.json` 等 JSON 写入统一改为 atomic write；同一路径的并发写入按顺序提交，避免旧快照覆盖新快照。
- 读取损坏配置时先备份为带时间戳的 `.corrupt` 文件，再加载安全默认值并向 UI 返回“已保留损坏文件”的提示，不再静默吞掉用户配置。
- 受保护 prompt 改为在发送给 worker 前完成追加并等待写入；按完整 canonical session path 生成无碰撞文件名；启动恢复后按消息内容/时间戳对账，已接管的记录自动清理。
- 对 loaded-session 条目做 schema 校验、路径归一化、过期/已归档清理，并持久化标题、时间和消息计数，减少重启后 cwd 占位标题或重复会话。
- `/undo` 的多文件恢复增加预检和逐文件结果记录；失败时明确哪些文件未恢复，避免出现 UI 已回退但磁盘只恢复一半的假象。

**验收**

- 在写入配置/会话索引过程中模拟进程退出，重启后文件始终是完整旧版本或完整新版本，不出现半个 JSON。
- 首条 user 消息在 worker 尚未产生 assistant、停止或崩溃后仍可恢复且不重复显示。

### 阶段 4：IPC、文件和网络边界防护（P1）

**涉及文件**

- 新增 `src/main/ipc-validation.ts`；修改 `src/main/index.ts`、`src/main/browser/ipc.ts`、`src/main/providers.ts`、`src/shared/openai-models.ts`、`src/shared/provider-connection.ts` 及相关类型/测试。

**行为**

- 为 session、workspace、provider、browser registration、restore、vision upload、agent options/command 添加运行时校验，不把 TypeScript cast 当作安全边界。
- 增加统一上限：prompt/单个 RPC 行、恢复批次和总字节数、单文件读取量、图片数量与总大小、浏览器 tab 快照和下载记录；超限返回可理解错误，不进入 worker 或一次性读入内存。
- `workspace:read` 先通过 `stat`/流式读取执行上限；restore 预检所有路径并继续使用 realpath/工作区约束，减少部分写入和 symlink 边界问题。
- 模型发现、连接测试、余额查询、更新检查等网络请求统一使用 AbortController 超时；超时、重试和用户主动停止不重复提交有副作用的 prompt。
- RPC 单行解析增加最大行长和协议错误诊断；stderr/错误消息做密钥与凭据脱敏。

**验收**

- 恶意或损坏 IPC payload、超大图片/恢复内容、畸形 RPC 输出都只产生受控错误，不导致主进程崩溃或内存无界增长。

### 阶段 5：本地诊断、崩溃恢复和故障回归（P1/P2）

**涉及文件**

- 新增 `src/main/local-logger.ts`、`src/renderer/ErrorBoundary.tsx`（或等价实现）。
- 修改 `src/main/index.ts`、`src/main/agent-host.ts`、`src/renderer/main.tsx`、`src/renderer/App.tsx`、浏览器组件和 `package.json`。
- 新增/更新 `src/main/agent-lifecycle.test.ts`、`src/main/browser/automation-concurrency.test.ts`、`src/main/rpc-lines.test.ts`、renderer 会话恢复测试及 browser smoke 脚本。

**行为**

- 记录本地、限大小、可轮转的结构化诊断：启动失败、worker exit/error、请求超时、renderer gone、browser guest gone、配置恢复；不上传，不记录 API key、prompt 原文或完整代码。
- 为关键错误保留 session/runtime、阶段、可重试性和下一步操作；renderer 出错时显示恢复按钮，主进程初始化失败时显示可诊断启动错误。
- 增加故障注入覆盖：快速 A/B 切换、重复 start、worker SIGTERM/SIGKILL、EPIPE、超时、非法 JSON、renderer reload、并发配置写入、损坏配置恢复、首条 prompt 崩溃、browser guest 销毁/导航竞态、下载清理和应用退出。
- 将 `pnpm test:browser` 纳入稳定性检查说明；完成 `pnpm typecheck`、`pnpm test`、`pnpm build`、`pnpm test:browser`、`git diff --check`。
- 在 macOS 与 Windows 分别手工验证：多会话并行、应用退出无孤儿进程、沙箱模式、renderer 重载、独立浏览器窗口恢复。

## 建议落地顺序

1. 先做阶段 1 和阶段 3：它们直接解决“命令跑错会话”和“消息/配置丢失”这两类高代价问题。
2. 接着做阶段 2：多会话功能已经存在，但浏览器的全局状态目前是最大的交叉污染风险。
3. 再做阶段 4、5：把输入边界和故障证据补齐，避免问题只能靠用户截图复现。
4. transcript 虚拟化、后台会话多窗口监控等体验型优化放在上述稳定性基线之后，避免掩盖生命周期问题。

## 预期结果

- 会话切换具备明确的 runtime 隔离和可恢复快照，不再依赖事件“恰好没有错过”。
- 配置与首条消息具备崩溃安全的持久化路径。
- 浏览器、worker、下载和 watcher 的生命周期可收敛，不因长期运行持续积累资源。
- 超大/非法输入和网络异常被限制、超时并可诊断。
- 现有功能与未提交 renderer 改动保持不变，最终以类型检查、全量单测、构建和 Electron browser smoke 作为交付门槛。
