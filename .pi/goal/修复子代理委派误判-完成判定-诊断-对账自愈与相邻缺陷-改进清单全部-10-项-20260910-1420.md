# Goal

修复委派协调器（`src/main/delegation-coordinator.ts`）把"prompt 接收即返回"误判为"子代理已完成"导致的委派失败误报，并按已确认的改进清单（P0/P1/P2 全部 10 项）补齐等待原语、失败分类、诊断、对账自愈、资源兜底、UI 出口、语义对齐、测试基线与相邻缺陷。

对账回填语义（已确认采用推荐方案）：**不新增 `recovered` 状态**——历史 `failed` 记录若子会话 JSONL 末尾确有 assistant 文本，则回填报告、置为 `completed`、清除过期的 error，恢复事件写入诊断日志。

# Acceptance criteria

**P0 — 完成判定与等待原语**
1. 协调器不再把 `prompt` 的响应当作子代理完成依据：判定前必须等到子代理空闲/结束。存在单测：注入的假 host 上 `prompt` 立即 resolve、报告在约 3 秒后才出现在子会话消息里 → 委派最终 `completed` 且报告完整（而非 `failed`/空报告）。
2. `AgentHost` 新增公开 `waitForIdle()` 等待原语（以 `agent_start`/`agent_settled` 驱动，worker 空闲时立即 resolve）；`LONG_RUNNING_REQUESTS` 中 `prompt` 的"接收即返回"语义在代码注释与 `src/shared/agent-protocol.ts` 契约说明中写清。单测覆盖：空闲立即 resolve、生成中等到 `agent_settled` 后 resolve。
3. 失败原因分类：`worker_exit`（附退出码 + stderr 摘要）/ `no_report` / `timeout` / `cancelled` 不再共用同一句文案；错误信息包含 childSessionPath、childRuntimeId、最后一条消息的 role/type、turns/toolCalls、耗时。单测覆盖四种可区分的失败路径。
4. `pnpm test` 全绿，含 `src/main/agent-subagents.test.ts`（当前已通过，必须保持通过）。

**P1 — 可发现、可自愈**
5. 协调器支持注入 `DiagnosticSink`（主进程 `index.ts` 传入现有 `diagnostics` 实例），在启动/判定/结束、判定依据（消息条数与最后 role）、worker 退出码、子会话路径处留诊断记录；单测断言 sink 收到启动与失败记录。
6. 对账回填：协调器启动/水合时，对 `failed` 且子会话 JSONL 末尾有 assistant 文本的记录回填报告并置 `completed`；子会话确无文本的 `failed` 保持 `failed`。单测覆盖这两种路径。
7. 不出现"状态 failed/cancelled + 进程仍在跑"的并存终局：确认结束前不下失败终态（真失败/取消时显式 `host.stop()` 并记录）。单测断言取消路径先等待停止完成再落终态。
8. 失败态 UI 出口：委派失败卡片/详情可见子会话标识（childSessionPath）与 delegate 工具 recent 活动缓冲的最后几条，而非仅一句占位文案；以渲染层现有测试模式写可断言的单测。

**P2 — 一致性与相邻缺陷**
9. 两套委派实现的"完成"判定语义一致：抽出共享的"等待空闲 + 提取最后 assistant 文本"收集策略（或共享模块），coordinator 与 `src/runtime/tools/delegate.ts` 均基于它，代码可查。
10. 相邻缺陷修复（各带单测）：`continue` 的重启分支不再是死代码（host 缺失时可实际重启并完成）；持久化保存 permission，水合不再硬编码 `"auto"`（恢复后 permission 保留原值）。
11. 新增纯逻辑竞态用例（注入假 createHost，不真实 spawn worker）：报告延迟产出、worker 中途被 kill、真无文本、超时、failed→completed 对账、2 个并发委派报告不串——全部通过。
12. `pnpm test` 与 `pnpm typecheck` 全部通过。

# Boundaries

- 不修改 pi 运行时（`node_modules`、`dist/` 构建产物）：RPC"接收即返回"语义按现状适配，只在 TACode 壳层（`src/`）内修复。
- 不回滚、不破坏工作区现有未提交改动（`src/renderer/` 子代理展现、`src/runtime/tools/delegate.ts` 等），在其基础上继续。
- 不创建 git 提交、不推送；`features.json`（如存在）只改 `passes`，不删条目、不改 `description`。
- 端到端测试保持真实 spawn worker 且不削弱断言；不为过测而放宽竞态检查。
- 面向用户的文案用简体中文；代码、路径、命令保持原文。
- 不上传任何日志/数据；诊断仍只写本机。
