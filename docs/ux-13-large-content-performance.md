# 长内容回放

使用真实 Electron、preload 和生产 renderer，本地临时项目与合成消息；不调用模型。基线 `e08da55`，两种构建各 3 轮独立进程，固定窗口 1440 × 960，无并行测试负载。原始记录与设备见 [JSON](ux-13-large-content-measurements.json)。

样本为 2000 轮历史、102498 字节中文回答、105779 字节代码和恰好 4 MiB 文件。回答分 40 次追加，每次间隔 25 ms；每 5 次经 Electron 插入文字并等下一帧，记录输入响应。各阶段时间包含 IPC、渲染和等待条件的开销；长任务来自 PerformanceObserver，按任务开始时刻归属阶段。

| 指标 | 基线 | 优化后 |
| --- | ---: | ---: |
| 打开历史，中位数 | 57.9 ms | 71.2 ms |
| 固定流式回放，总时间 | 1287.7 ms | 1441.0 ms |
| 回答结束至两帧后 | 113.1 ms | 97.2 ms |
| 长代码出现（含滚动跟随） | 1426.0 ms | 1301.7 ms |
| 4 MiB 文件正文出现 | 476.7 ms | 175.9 ms |
| 原生查找文件末尾 | 162.0 ms | 134.9 ms |
| 流式输入 p95，合并 24 个样本 | 19.5 ms | 19.5 ms |
| 每轮最长主线程任务，中位数 | 349 ms | 151 ms |
| 每轮长任务累计，中位数 | 498 ms | 266 ms |
| 文件面板元素数 | 32851 | 17 |

主要收益是大文件 DOM 和排版开销。历史打开与流式输入没有可证实的加速；流式总时间仍受固定等待和调度影响，不能据此宣称所有阶段更快。长代码出现还包含滚动跟随，不等同于纯高亮耗时。4 MiB 文本的浏览器排版和全文查找仍会出现长任务。

同步高亮预算为 32 Ki 个 UTF-16 code unit、512 行、单行 2000 字符。超出后显示完整原文，省去行号和语法 token 节点；仍可原生查找、选择和完整复制。4 MiB 读取边界沿用 UX-10。普通短代码继续高亮。定稿复用流式分段边界并关闭尾部修补，不再重新拆成大量单块。

`TACODE_LARGE_SMOKE=1 node scripts/test-session-activity.mjs` 校验历史窗口化、回答每段及末尾完整、回答复制、长代码精确复制、文件末尾原生搜索和 4 MiB 精确复制。`TACODE_LARGE_RUNS=3` 重复三次。比较构建增加 `TACODE_ACTIVITY_BASELINE=1 TACODE_ACTIVITY_BASELINE_REF=e08da55`。

ResizeObserver 诊断：`TACODE_RESIZE_DIAGNOSTIC=1` 记录交付前的目标与尺寸。警告伴随 virtua 包装行和 messages 高度变化，依赖库在 ResizeObserver 中同步更新虚拟列表；应用侧宽度、工具栏和输入区留白的布局写入已延后到下一帧，警告仍存在（各轮约 9–12 次）。这不是已修复的警告，也没有据此修改全局 ResizeObserver 或隐藏所有 renderer 错误。后续需要针对虚拟列表测量与跟随滚动继续处理，当前回放未出现内容丢失或交互锁死。
