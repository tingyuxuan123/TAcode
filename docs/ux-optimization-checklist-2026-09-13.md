**TACode 使用体验优化清单**

评估日期：2026-09-13。阅读基准为当日工作区，参考提交 `f725aaf`。本清单沿着启动、打开历史、输入与发送、后台执行、停止、文件浏览和设置操作梳理，交付范围为源码评估与优化建议。

最值得先改善的是：用户已经输入的内容能够保住，需要用户处理的事情能够看到，浏览历史和文件能够立即得到可信的结果。代码拆分和缓存调整应服务于这些结果。

优先级表示建议实施顺序：P0 为流程可靠性，P1 为日常高频体验，P2 为长时间使用和进阶场景。下文区分“代码确认”“性能待测”“产品建议”；代码路径确认不等于已经用真实界面复现所有症状。工期是单人实现加针对性验证的粗估，跨平台兼容可能增加成本。

- [x] **UX-01 · 后台审批、失败和完成状态可恢复**

  **代码确认。** 主会话事件路由在发现事件不属于当前会话后，仅处理开始和结束事件就返回；审批处理位于此判断之后。后台错误也被直接过滤。切换会话会清空当前审批，而快照回放主要恢复消息与统计，不能据此恢复已经挂起的审批。用户在 A 运行时切到 B，A 随后申请权限或询问问题，就存在等待入口不可见的风险。这里指后台主会话；委派子会话已经有单独的审批状态保存与展示。

  **建议行为。** 每个会话保存“运行中 / 等待处理 / 失败 / 完成未读”状态；侧栏有持续标记，点击能定位到请求或错误。恢复快照时返回仍有效的请求，答复按会话和运行句柄路由，已答复请求不重复出现。完成提示可以短暂显示，待处理事项应保留到用户处理。

  **验收。** A 运行时切到 B，A 发起确认后 B 的输入不被打断，侧栏出现待处理标记；切回 A 或重载渲染界面后，确认卡仍可操作且只答复一次。后台失败能查到原因，不能统一提示为成功完成。

  **定位与风险。** [主会话事件路由](/Users/yfdl/project/TAcode/src/renderer/App.tsx:1538)、[快照恢复](/Users/yfdl/project/TAcode/src/renderer/App.tsx:883)、[AgentHost.snapshot](/Users/yfdl/project/TAcode/src/main/agent-host.ts:214)。风险中等，重点是过期请求、重复事件和并发会话隔离。

- [x] **UX-02 · 完整草稿保存与发送失败恢复**

  **代码确认。** `PromptBar.sendNow` 在调用父层发送前清空文字和附件；`sendMessage` 的失败分支只通过 `fillPrompt(text)` 恢复文字。输入内容由组件局部状态管理，没有按会话保存的完整草稿；切项目和新建会话还会显式清空文字。现有 composer memory 保存的是模式与模型。

  **建议行为。** 按项目及会话保存包含文字、图片、文件引用的草稿。发送开始时保留完整副本，明确被接收后再提交清空；发送被拒绝时恢复完整内容。恢复旧副本不得覆盖用户在等待期间新输入的内容。已发出但模型回答失败，应在原消息上重试，避免重复发送。

  **验收。** 带两张图片发送，分别触发模型未配置、启动失败、发送拒绝，内容均可完整恢复；A/B 会话来回切换能找回各自草稿；请求失败前又输入的新文字得到保留。重启后的文字草稿也可恢复，图片缓存有大小和清理边界。

  **定位与风险。** [PromptBar.sendNow](/Users/yfdl/project/TAcode/src/renderer/ui.tsx:2519)、[sendMessage](/Users/yfdl/project/TAcode/src/renderer/App.tsx:1358)、[composer-memory.ts](/Users/yfdl/project/TAcode/src/renderer/composer-memory.ts:7)。风险中等，重点是发送确认边界、草稿版本和图片存储。

- [x] **UX-03 · 中文输入法与快捷键兼容**

  **代码确认，需实机回归。** 普通 Enter 发送检查了 `isComposing`，但斜杠命令和文件补全分支先处理 Enter、方向键与 Escape，尚未检查组合输入状态。会话重命名也直接用 Enter 触发失焦提交。

  **建议行为。** 在处理补全、命令、发送和重命名快捷键前统一识别输入法组合状态；输入法确认优先，确认后再次按 Enter 才执行界面动作。Escape 关闭补全时保留用户已经输入的内容。

  **验收。** macOS 和 Windows 中文输入法下，在 `@` 文件补全、`/` 命令候选和会话重命名中确认候选词，不触发额外操作；普通 Enter 发送、Shift+Enter 换行继续正常工作。

  **定位与风险。** [PromptBar.onKey](/Users/yfdl/project/TAcode/src/renderer/ui.tsx:2532)、[SessionRow 重命名](/Users/yfdl/project/TAcode/src/renderer/App.tsx:220)。风险低，浏览器合成键盘事件不能完全替代实际输入法验证。

- [x] **UX-04 · 统一新建、切换与后台运行规则**

  **代码确认 + 产品建议。** 当前切项目允许旧任务继续后台运行，但 `newThread` 会对当前会话执行 abort 和 stop。两种看起来相近的导航操作，执行生命周期不同。普通主会话的侧栏也没有像委派子会话一样接入停止入口。

  **建议行为。** 推荐将普通“新建对话”定义为打开空白对话，正在执行的旧任务继续运行，并在侧栏显示状态；停止由明确的停止操作完成。所有运行中的会话均可从侧栏停止，无需切入。

  **验收。** A 正在执行时新建 B，A 的任务继续且有运行标记；侧栏能单独停止 A，B 的草稿和任务不受影响；快速新建、切换、停止不会把命令发往错误运行句柄。

  **定位与风险。** [bindProject](/Users/yfdl/project/TAcode/src/renderer/App.tsx:1102)、[newThread](/Users/yfdl/project/TAcode/src/renderer/App.tsx:1141)、[SessionRow 调用](/Users/yfdl/project/TAcode/src/renderer/App.tsx:2004)。风险中等，属于需要明确产品语义的行为调整；依赖 UX-01 的后台状态可靠性。

- [x] **UX-05 · 历史先展示，继续对话时再准备运行环境**

  **代码确认。** 主区打开历史走 `startAgent`：先检查模型配置，再启动或复用 worker、取快照；没有配置时提前返回并打开设置。查看旧记录因此依赖运行环境。项目已有不启动 worker 的只读转录接口，子会话面板正在使用它。

  **建议行为。** 点击历史先展示本地转录或缓存，继续发送时再检查模型、准备 worker。加载期间保留明确的会话标题和骨架；空会话、加载失败各有独立状态。活动会话在接入实时流时用序号对账，避免丢消息或重复。

  **验收。** 删除模型配置后仍能阅读已有会话；纯浏览多个已结束会话不增加 worker 数量；快速切 A/B 只显示最终选中的会话；长历史可以继续加载更早内容，不能把只读接口现有的 4 MiB / 2000 条尾部限制当作完整记录。

  **定位与风险。** [openSession / startAgent](/Users/yfdl/project/TAcode/src/renderer/App.tsx:790)、[readSessionTranscript](/Users/yfdl/project/TAcode/src/main/session-transcript.ts:76)。风险中等，转录读取还需保留会话分支、压缩、存储路径恢复与实时事件对账语义，不能简单替换一次 API 调用。

- [x] **UX-06 · 启动先显示窗口，历史整理后台完成**

  **代码确认，整机耗时待测。** 创建窗口之前等待 `initializeTacodeHome`，其中每次都执行现有会话分区。分区串行处理扁平 JSONL，包含读取头部和目录、权限等操作。

  **建议行为。** 只把安全打开应用所需的最小目录准备放在窗口之前；旧记录整理按需或后台增量完成。侧栏先给可用记录，持续整理时提供轻量状态，并支持失败后重试。首次迁移和新产生记录都要覆盖，不能仅靠永久 marker 跳过所有后续整理。

  **验收。** 在固定设备、相同构建上比较 0 / 100 / 1000 个会话，分别记录“窗口出现”和“侧栏可操作”时间；窗口不再等待全部历史扫描。中途退出后再次打开不会漏记录或重复迁移。

  **定位与风险。** [启动链路](/Users/yfdl/project/TAcode/src/main/index.ts:2211)、[initializeTacodeHome](/Users/yfdl/project/TAcode/src/runtime/home.ts:47)、[partitionExistingSessions](/Users/yfdl/project/TAcode/src/runtime/home.ts:163)。风险中等，需要保留迁移和硬链接恢复的正确性。

- [x] **UX-07 · 会话列表增量更新**

  **代码确认 + 合成测量。** `listTacodeThreads` 每次创建 store、refresh、查询、关闭；refresh 遍历会话并执行分区/索引。前端又在标题变化和任务结束时请求列表。现有索引已用文件元数据跳过未变内容的解析，但文件枚举与分区工作仍会发生。本次临时合成样本中，1000 个未变会话的一次列表调用约 200ms；这是辅助函数耗时，不是整段界面延迟。

  **建议行为。** 主进程复用状态连接；合并同一时段的列表刷新，优先更新已知变化的会话。定期或启动后的全量核对负责发现外部修改。前端立即更新当前行，后台对账，使用请求版本避免旧响应覆盖新结果。

  **验收。** 多个会话同时结束时，索引工作按一批变化合并；重命名、置顶、归档后不闪回旧状态；1000 个会话中只改一条时不重新处理全部记录；外部创建和删除的转录最终仍能被发现。

  **定位与风险。** [listTacodeThreads](/Users/yfdl/project/TAcode/src/runtime/state.ts:509)、[TacodeStateStore.refresh](/Users/yfdl/project/TAcode/src/runtime/state.ts:208)、[列表刷新触发](/Users/yfdl/project/TAcode/src/renderer/App.tsx:1528)。风险中等；复用连接与减少全量扫描需要一起处理，单独换单例收益有限。

- [ ] **UX-08 · 缩短命令前后的文件检查**

  **代码确认 + 合成测量。** `exec_command` 的 checkpoint 在执行前后读取、哈希工作区文本文件。临时合成样本中，1000 个约 8.5 KB 文本文件包围一次空操作，约耗时 170ms，发生约 2000 次文件读取。代码中的 2000 文件判断位于递归目录入口，同一大目录仍可能超过该数量。

  **建议行为。** 先记录检查耗时与覆盖范围，再建立可靠的文件变化候选集合，减少未变化文件的重复读取，处理好异步运行命令的检查时机。检查较慢时显示明确阶段，让用户知道是在准备命令还是执行命令。

  **验收。** 同一代表性项目中对简单命令连续测量，分别统计检查与命令本身耗时，优化后检查耗时明显下降；新增、删除、重命名、同大小覆写仍能正确撤销；超限范围有说明。

  **定位与风险。** [captureWorkspaceCheckpoint](/Users/yfdl/project/TAcode/src/runtime/tools/checkpoint.ts:46)、[exec_command 接入](/Users/yfdl/project/TAcode/src/runtime/tools/commands.ts:264)。风险较高，涉及撤销正确性。`mtime + size` 不能单独证明内容未变；只看命令名或 `git status` 也不足以覆盖普通 shell 命令和未跟踪文件。建议先做 UX-06/07 等边界更清晰的性能项。

- [ ] **UX-09 · 文件搜索范围正确、结果完整**

  **代码确认。** 文件面板文案是“搜索工作区文件”，实现却先把所有路径折叠到当前目录的第一层，再筛选候选。例如从根目录搜 `App.tsx`，`src/renderer/App.tsx` 会先变成 `src/`，无法命中。另外，工作区列表默认限制总文件数 8000、每目录 200，结果类型没有截断信息；输入框文件补全也使用这份列表。

  **建议行为。** 浏览目录与搜索工作区分开处理：无查询时列当前目录，有查询时按完整路径检索，显示相对路径。目录按需读取或分页，搜索不依赖被截断的浏览列表。文件面板和 `@` 补全共享按项目维护的索引，变更按路径增量更新。

  **验收。** 根目录能搜到深层的 `App.tsx`；同目录第 201 个文件可浏览和引用；超过 8000 文件的仓库可检索后部文件；加载失败与“没有匹配”分开；连续文件变化不会让两个组件重复全量扫描。

  **定位与风险。** [FilesPanel.visible](/Users/yfdl/project/TAcode/src/renderer/browser/files-panel.tsx:48)、[listWorkspaceFiles](/Users/yfdl/project/TAcode/src/main/index.ts:2129)、[PromptBar 文件列表](/Users/yfdl/project/TAcode/src/renderer/ui.tsx:2396)。风险中等。修正搜索过滤本身可先单独完成，索引与分页随后实施。

- [ ] **UX-10 · 文件预览及时刷新并区分状态**

  **代码确认。** 文件标签和抽屉仅在路径、项目或语言变化时重新读取；打开后同一个文件被 Agent 或外部编辑器修改，不会自动刷新文本。主进程还把文件不存在转为成功的空字符串，界面难以区分空文件与已删除文件。

  **建议行为。** 活动预览订阅相关文件变更，隐藏预览先标记待刷新、激活时更新；保留滚动位置和选择。提供刷新入口，分别显示加载、真实空文件、已删除、二进制、读取失败和内容截断状态。复制内容时不要混入“仅显示开头”等界面提示。

  **验收。** 文件打开后修改并保存，活动预览在约 1 秒内更新且不跳回顶部；删除文件明确显示不存在；空文件显示为空文件；读取失败可重试；大文件截断提示不被当作正文复制。

  **定位与风险。** [FilePanel](/Users/yfdl/project/TAcode/src/renderer/browser/file-panel.tsx:18)、[FileDrawer](/Users/yfdl/project/TAcode/src/renderer/ui.tsx:2019)、[workspace:read](/Users/yfdl/project/TAcode/src/main/index.ts:737)。风险低到中等，重点是文件变更合并、项目隔离和过期读响应。

- [ ] **UX-11 · 多个聊天面板保持流畅**

  **代码确认，实际帧耗时待测。** 主会话已有按动画帧合批和虚拟列表；子会话、侧边聊天仍在事件到达时调用消息更新，子会话使用全量 `groups.map`。多个非活动面板通过 `display: none` 保持挂载，其订阅与计算也仍存在。React 自身可能合并部分更新，不能把“每个事件调用更新”直接等同于“每个事件都提交一帧”。

  **验收。** 用固定事件速率回放主会话加 3 个子会话，记录输入响应、长任务和 React 提交耗时；隐藏面板的渲染工作明显下降，切回内容完整；审批、失败和完成状态仍即时更新，后台任务正常执行。

- [ ] **UX-12 · 停止过程有反馈、超时可处理**

  **代码确认，内存与耗电收益待测。** AgentManager 保留会话 worker，缺少空闲预算；命令队列 Map 保留已完成链，浏览器自动化的 session Map 在 reset 时清引用但未删除条目；回放缓存仅限 500 个事件，未限制总字节。macOS 关主窗口时还未关闭工作区 watcher。委派等待使用 25ms 轮询，轮数看门狗在配置 maxTurns 时每 500ms 拉取消息。

  **验收。** 顺序浏览/运行并结束 50 个会话后，空闲 worker、Map 条目和监听器数量回到约定范围；打开再关闭窗口不累加监听；无任务时减少定时唤醒；运行中、等待审批和仍有子任务的会话不被当作可回收空闲会话。

  **定位与风险。** [AgentManager](/Users/yfdl/project/TAcode/src/main/agent-manager.ts:65)、[浏览器会话状态](/Users/yfdl/project/TAcode/src/main/browser/automation.ts:53)、[关窗清理](/Users/yfdl/project/TAcode/src/main/index.ts:531)、[委派等待](/Users/yfdl/project/TAcode/src/main/delegation-coordinator.ts:327)。风险中等，先测长时间运行的资源曲线，避免把所有常驻缓存都视作泄漏。

建议先完成 UX-01、UX-02，并穿插 UX-03、UX-09 的搜索语义修正、UX-10 这几项改动集中的工作。随后推进历史读取、启动和会话索引，再处理 checkpoint、多面板和停止路径。每次只交付能独立验证的变化；表中工期不能简单相加为排期，几项底层工作可以复用。

已有的主消息流合批、虚拟列表、阅读位置记忆、停止中提示、失败恢复、文件读取上限、连接测试、Skills/MCP 编辑保护，应作为回归基线。比如 [useFollowScroll](/Users/yfdl/project/TAcode/src/renderer/use-follow-scroll.ts:29) 已按会话范围保存位置，[MessageList](/Users/yfdl/project/TAcode/src/renderer/message-list.tsx:229) 已使用 Virtualizer，优化不能破坏这些能力。

实施时为对应路径补必要的自动化回归，并运行项目现有 `pnpm test`、`pnpm typecheck`；主界面操作还要做针对性浏览器/桌面验证。输入法、实际停止与跨平台进程回收需要实机覆盖。PR 常规 CI 值得尽早补齐，作为这些体验修改的保障。

本清单中的合成耗时仅帮助排序，临时样本不是完整应用基准。正式性能验收应固定设备、构建、数据集和事件速率，分别记录用户动作到反馈、窗口出现、列表可用、命令准备以及渲染长任务；建议以 100ms 内可见操作反馈为一般交互目标，异步操作耗时更长时持续展示真实状态。
