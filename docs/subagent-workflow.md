# TACode 子代理工作流

主代理负责设计、复杂实现、范围决策和最终整合。简单任务、强依赖步骤由主代理直接完成；只有任务可以独立交付，且并行能减少等待或隔离较多探索上下文时才委派。

## 现有角色

沿用 TACode 的四个角色，通过 `delegate` 的 `role` 选择当前已启用的定义：

| 角色 | 适合的任务 | 边界 |
| --- | --- | --- |
| `explorer` | 已知范围的事实抽取、实现定位、调用链与影响范围分析 | 先查给定路径，必要时再扩大；命令只允许只读白名单 |
| `code-reviewer` | 指定变更的独立正确性、安全、并发和契约审查 | 主代理提供 diff 或路径及要求；没有命令工具，不把代码推断当成实测结果 |
| `test-runner` | 指定命令、环境与范围的本地验证 | 不修改业务代码、测试断言或依赖；允许授权检查的常规临时产物 |
| `fixer` | 文件清单、转换规则、排除范围和验收方法均明确的机械修改 | 保留协作者已有修改；设计、公共接口变更与复杂实现交回主代理 |

`explorer` 根据任务范围承担参考方案中事实抽取、一般证据整理和复杂调用链分析的职责。各角色达到完成条件即结束，轮次上限不是需要用满的预算。

## 派发与收敛

- 通常同时使用 1–3 个子代理；当前运行时硬上限为 8。超过通常数量前，先评估独立性、共享工具或文件状态和整合成本。
- 新委派不复制父对话。主代理应传入必要事实；独立审查只给中立的变更范围、要求和证据，不附带预设结论。
- 同类后续问题优先用 `delegate_continue` 复用已完成代理，并补充已采纳事实与剩余问题。桌面路径保留子会话历史；CLI fallback 会根据原任务和后续指令重新运行，因此后续指令也应自包含。
- 有独立工作可做时使用 `background: true`，派发后继续主代理的工作，不重复检索子代理负责的问题。
- 下一步确实依赖未完成结果时才调用 `delegate_wait`，指定需要的 `delegationIds` 和有界 `timeoutSeconds`，通常为 30–60 秒。结果已到达就直接处理。
- 超时后根据实际进展判断继续等待、缩小任务或接手，不机械轮询；接管写入文件前先停止对应子代理。
- 采纳充分可信的证据；只复核冲突、关键高风险结论和修改后的最终行为，不默认重读全部文件、重跑全部检查。

任务说明可以按以下模板填写 `task`：

```text
目标：一个可以独立交付的问题或转换。
范围：工作目录、具体文件/符号/日志范围，以及明确排除的部分。
已知事实：必要证据与已完成检查；独立审查不提供预设结论。
限制：允许的工具/命令、环境、是否可写；不能变更的内容。
完成条件：需要回答的问题或验收命令，证据充分即可停止。
若需修改：明确文件所有权、转换规则和排除项；保留其他协作者的修改。
```

## 回报约定

最终报告首行是以下状态之一，再用简体中文给出结论、关键证据和限制，代码、路径、符号和命令保留原文：

| 首行 | 含义 |
| --- | --- |
| `complete` | 已满足本次委派的完成条件 |
| `partial` | 已有可用结果，但仍有未完成或需主代理决策的部分 |
| `blocked` | 缺少必要前提，需要主代理提供信息或调整任务 |

报告通常控制在约 1500 字符，优先放结论与关键 `path:line` 或实际命令结果；短引文只用于支撑发现，不强制为每一句话重复引用源码。区分实际观测、推断与未覆盖分支，不为内部沟通创建报告文件。

当前子代理没有独立消息工具。通常只返回最终报告；遇到阻塞、重大反证或需要主代理决策的阶段性结果时，停止相关工作并提前返回 `partial` / `blocked`。工具活动仍会显示在界面上，无需模型发送固定进度心跳。子代理不得通过工具、命令或其他 CLI 再派生代理。

报告首行描述任务完成度，运行时状态描述一次运行是否结束；运行时显示 `completed` 不能代替主代理检查报告中的缺口。

## 定义与模型

内置定义在 [`src/runtime/subagents.ts`](../src/runtime/subagents.ts)，主代理规则和两条执行路径共用的子代理约束在 [`src/shared/subagent-prompts.ts`](../src/shared/subagent-prompts.ts)。用户可在设置 → 子代理中编辑；用户文件位于 `~/.tacode/subagents/<name>.md`，同名定义覆盖内置定义，启用状态单独保存。

内置角色未钉选模型，沿用当前会话模型；已有用户定义中的模型、思考等级和权限配置继续生效。选择模型时使用自己已配置且可用的 AI 服务，无需照搬参考方案中的模型名称。内置 prompt 更新不会覆盖已保存的同名用户文档；自定义角色也会收到运行时的通用约束。

源码更新后需要重新构建并完整重启 TACode，再启动新的 Agent 会话，桌面主进程和子 worker 才会使用新规则。
